# 구매계약 종료 예정·알림 조회

## 사용 시점

- "A 차장 구매계약 언제까지야?"
- "B 업체의 10월 계약 종료 예정 인력 알려줘."
- "처리 안 한 계약 만료 알림 있어?"
- (구현 예정) "11월 구매계약이 필요한 인력 리스트 뽑아줘."

## 필수 입력

| 요청 | 필수 입력 | 없을 때 |
| --- | --- | --- |
| 개인 계약 기간 | 인력(관리번호로 확정) | `find_people`로 찾고 동명이인은 선택 요청 |
| 종료 예정 인력 | 연도, 월 / 선택: 업체명 | 연도가 없으면 기준일의 연도로 보고 답변에 밝힌다. 월이 없으면 물어본다 |
| 미처리 알림 | 없음 | - |

## 실행 절차

1. 개인 계약: `find_people` → 1명 확정 → `list_contracts(person_id)`.
   여러 계약이 있으면 기준일에 유효한 계약과 연장(후속) 계약을 구분해 보여준다.
2. 종료 예정: `contracts_ending(year, month, company)`. 업체명은 등록된 이름과 같아야 한다.
   결과가 없고 업체명이 애매하면 업체명을 확인한다.
3. 미처리 알림: `pending_contract_alerts()`. 종료 14일 전부터의 미확인 알림이다.
4. 월별 구매 필요 인력: `monthly_purchase_needs`를 호출한다. 이 도구는 **구현 예정**이라 실패를 돌려준다.
   판정 기준이 미확정이라고 답하고, 대신 해당 월 종료 예정 계약(`contracts_ending`)을 참고 정보로 제공할지 묻는다.

## 연결 도구

| 도구 | 상태 | 용도 |
| --- | --- | --- |
| `find_people` | 구현 | 인력 확정 |
| `list_contracts` | 구현 | 인력의 계약 목록(상태·기간·연장 여부·만료 상태) |
| `contracts_ending` | 구현 | 월·업체별 종료 예정 |
| `pending_contract_alerts` | 구현 | 미확인 만료 알림 |
| `monthly_purchase_needs` | 구현 예정 | 구매 필요 판정 (기준 TODO) |
| `query_database` | 구현 | 그 밖의 조건 조회·건수 집계 (SELECT만) |
| `prepare_contract_save` | 구현 | 계약 등록·수정 확인 카드 준비 (저장 안 함) |
| `prepare_contract_delete` | 구현 | 계약 삭제 확인 카드 준비 (삭제 안 함) |
| `prepare_alert_ack` | 구현 | 알림 확인 처리 확인 카드 준비 (저장 안 함) |

## 출력 형식

- 표: 이름 · 업체 · 계약번호(미발급이면 "미발급") · 상태(준비/확정) · 계약 기간 · 만료 상태(D-n / 오늘 종료 / 만료 n일 경과) · 연장 계약 등록 여부
- 기준일(Asia/Seoul)을 함께 밝힌다.
- 알림 '확인'과 계약 갱신 완료는 다르다는 점을 혼동하지 않는다.

## 예외 처리

- 계약이 없으면 "등록된 구매계약이 없다"고 답한다. `정` 분류 인력은 구매계약 대상이 아니다.
- `준비` 상태 계약은 계약번호가 없을 수 있다. 확정된 계약처럼 설명하지 않는다.
- 알림 확인 처리·계약 등록·수정·삭제는 `prepare_*` 도구로 확인 카드를 준비한다. 저장했다고 말하지 않는다.
- 도구가 `ok: false`이면 오류 내용을 전달한다.

## 성공 기준

- 날짜·건수가 도구 결과와 일치하고, 미확정 규칙(구매 필요 판정)을 추정해서 답하지 않는다.
- 평가 질문 `evals/questions.json`의 Q3~Q6 정답 도구를 따른다.
