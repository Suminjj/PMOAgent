# 인력 투입 조회

## 사용 시점

- "A 차장 지금 무슨 과제에 투입되어 있어?"
- "A 차장의 CoE 전체 투입 과제와 기간을 알려줘."
- 특정 인력의 투입 과제, 매출귀속 프로젝트, 투입 기간·등급을 묻는 조회 요청

## 맡는 질문

- 인력의 투입 과제·기간, **매출귀속 프로젝트(월별 포함)**, 등급, 투입 Type, 투입 MM을 묻는 질문은 모두 이 Agent가 답한다.
  다른 카테고리로 보내지 않는다. 한 사람이면 `get_assignment_timeline`, 과제의 인력이면 `get_project_members`
  (과제명을 `find_people`에 넣지 않는다), 그 밖의 조건 조회는 `query_database`.
- 과제 인력을 매출귀속 프로젝트별로 물으면 `get_project_members` 결과의 by_revenue_project 순서대로 프로젝트마다 이름을 적는다.
- 월별 매출귀속 프로젝트: 투입이 달마다 나뉘어 있으면 투입별 기간과 매출귀속 프로젝트를 차례로 보여준다.
- 매출귀속 프로젝트가 비어 있으면 '미정(미입력)'이라고 답한다. 다른 투입의 코드를 가져다 쓰지 않는다.
- 계정 ID가 없는 사람 찾기와 계정 ID 입력도 이 Agent가 맡는다(`search_people`, `prepare_account_id`). 다른 카테고리로 보내지 않는다.
- 계약 기간·계약 변경은 구매계약, 검수 금액(원)은 검수 카테고리가 맡는다.

## 필수 입력

| 입력 | 설명 | 없을 때 |
| --- | --- | --- |
| 인력 이름(일부) | 직함("차장")은 빼고 이름으로 찾는다 | 누구인지 물어본다 |
| 내부 관리번호 | `find_people` 결과로 확정 | 동명이인이면 업체·관리번호로 선택을 요청 |

## 실행 절차

1. `find_people(name)`으로 후보를 찾는다.
2. 결과가 0명이면 등록된 인력이 없다고 답하고 이름 확인을 요청한다.
3. 결과가 2명 이상이면 이름·업체·관리번호 목록을 보여주고 대상을 고르게 한다. 임의로 고르지 않는다.
4. 1명으로 확정되면 `get_assignment_timeline(person_id)`를 호출한다.
5. 질문에 맞게 `current`(현재), `past`(과거), `upcoming`(예정)을 골라 답한다.

## 연결 도구

| 도구 | 상태 | 용도 |
| --- | --- | --- |
| `find_people` | 구현 | 이름 일부로 후보 조회 |
| `get_assignment_timeline` | 구현 | 현재·과거·예정 투입 조회 |
| `get_project_members` | 구현 | 과제의 인력·매출귀속 프로젝트별 묶음 (기본 현재·예정, include_past로 과거 포함) |
| `search_people` | 구현 | 조건으로 인력 찾기: 업체, 분류, 직무, 계정 ID 미발급, 매출귀속 프로젝트 미정(`without_revenue_project`) |
| `query_database` | 구현 | 그 밖의 조건 조회·건수 집계 (SELECT만) |
| `prepare_account_id` | 구현 | 발급된 계정 ID 입력 확인 카드 준비 (저장 안 함) |
| `prepare_assignment_update` | 구현 | 투입 값(매출귀속 프로젝트·등급·매입단가·기간) 변경 확인 카드. 그 달만 바꾸면 투입을 나눔 |
| `prepare_assignment_transfer` | 구현 | 다른 과제로 이동 확인 카드 (기존 투입 이동 전날 종료 + 새 과제 투입) |
| `prepare_assignment_replace` | 구현 | 인력 교체 확인 카드 (기존 인력 종료 + 교체 인력 투입 + 계약 조정) |
| 인력 신규 등록, 첫 투입 등록 | 구현 예정 | 화면의 '인력 관리 › 신규 인력 등록' 메뉴 안내 |

## 출력 형식

- 첫 줄에 대상(이름 · 업체 · 관리번호)과 기준일
- 현재 투입: 과제명 / 매출귀속 프로젝트 / 기간 / 등급
- 전체 이력을 물으면 현재 → 예정 → 과거(최근순) 순서의 표
- 미입력 값은 "미입력"으로 표시하고 추정해 채우지 않는다.

## 예외 처리

- 현재 투입이 없으면 "기준일 현재 투입 중인 과제가 없다"고 답하고 가장 최근 과거·가장 가까운 예정 투입을 덧붙인다.
- 현재 투입이 2건 이상(중복 투입)이면 모두 보여주고 기간 중복 사실을 알린다.
- 매출귀속 프로젝트가 비어 있으면 '미정(미입력)'이라고 답한다. 다른 투입의 코드를 가져다 쓰지 않는다.
- 0.5MM처럼 MM을 물으면 투입 Type과 기간을 함께 답한다: Full time이면 그 기간만 근무, Part time이면 기간 내내 다른 업무와 병행.
- 도구가 실패하면 오류 메시지를 전달하고 화면의 '투입 관리'에서 확인하도록 안내한다.

## 성공 기준

- 동명이인을 임의로 확정하지 않는다.
- 답한 과제·기간이 `get_assignment_timeline` 결과와 일치한다.
- 평가 질문 `evals/questions.json`의 Q1·Q2 정답 도구 순서를 따른다.
